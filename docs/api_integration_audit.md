## Common HTTP contracts

Backend routes live beneath `API_BASE_URL`, which includes `/api`; root health is outside it. Flutter configuration: [ApiConfig](C:/Users/Asus/app_mobile/lib/config/api_config.dart). Explicit `API_BASE_URL` takes priority; debug Android candidates are USB loopback, optional `API_LAN_HOST`, then emulator loopback. The fixed personal LAN address and unused `AUTH_MODE` switch were removed. Authentication remembers the working base in `SecureApi.preferredBase`; search, profile and navigation use it. Debug HTTP is supported; release clients reject non-HTTPS APIs. Android's main manifest now denies cleartext, with a debug-only override.

**F** means `Authorization: Bearer <Firebase ID token>`, verified using Admin `verifyIdToken(token, true)`. Auth endpoints require F; other protected routes additionally resolve exactly one recognized Users row (**P**). Client-supplied user IDs are not authorization. See [verifyFirebase / requireProfile](C:/Users/Asus/app_mobile/backend_patch/middleware/identity.js), [SecureApi.request](C:/Users/Asus/app_mobile/lib/services/secure_api.dart).

**N** means P plus navigator role; navigation accepts only the account's phone source. **O** adds current device ownership. **C** means navigator self-access or an active, accepted caregiver relationship. `pairingService.authorize` checks C before and after sensitive reads, including Admin RTDB reads, because Admin bypasses client database rules.

Requests/responses use JSON, except root health. Successful legacy responses wrap `user`, `session`, or `sessions`; search returns an array. V2 returns the objects listed below. Errors use `{message}` and optionally `{code}`. V2 uses 400 malformed input, 401 missing/invalid identity, 403 wrong role/access, 404 absent resource, 409 conflicting state, 410 expired/consumed invitation, 429 rate limits, and sanitized 503 service failures. Auth/profile/navigation middleware can return 401/403/503. Profile/navigation retain sanitized 500 responses for operation failures. Protected profile/navigation/v2 and search responses use `Cache-Control: no-store`; auth responses contain profile data, not new application bearer tokens.

Server configuration is in [server.js](C:/Users/Asus/app_mobile/backend_patch/server.js). Production rejects insecure requests with 426. TLS termination requires an explicit `TRUSTED_PROXY_CIDRS` allowlist. Browser cross-origin access now requires `CORS_ALLOWED_ORIGINS` (comma separated); native clients are unaffected. JSON limits are 16 KB for v2 and 8 MB elsewhere for profile photos. Malformed and oversized bodies receive generic JSON 400/413; unexpected uncaught errors return generic 503. Actual proxy, TLS, CORS, and request-size behavior in a deployed environment remains untested.

## Findings and changes

Confirmed and fixed:

1. Registration unnecessarily sent passwords to the profile API, logged identity and raw responses, and could delete a Firebase account after an uncertain backend error. `AuthService.register/_postAuth` no longer does those things; malformed responses are sanitized. A UID is no longer returned as a fallback bearer token. `AppSessionService` purges legacy token/local-user storage and ignores legacy token arguments; protected requests obtain tokens from Firebase.
2. `profile PUT` treated omitted health fields as null and overwrote existing data. It now merges omitted fields within the transaction, retains the Users-row lock that serializes concurrent first saves, validates age/birthdate, handles connection-acquisition failure, and removes personal audit logs, raw database errors and table-name response metadata.
3. `navigation/start` cancelled/inserted sessions without a transaction, allowing concurrent active sessions. It now serializes per owner. Coordinates and summary metrics are validated. Client live updates used a resetting debounce that could postpone DB writes indefinitely under regular GPS updates; now throttled every8s. Late start responses and scheduled writes are guarded by identity revision. Non-2xx live/end responses are detected; failed end retains local retry state and generic `syncError` rather than silently acknowledging success.
4. Search used the wrong base after login failover, repeated successful empty results against a second provider, hid failures as no results, triggered public-provider autocomplete, and retried a wider backend search automatically. These paths were removed. Search is explicit, errors are distinct, and results require user selection. Input validation, bounded server cache/rate controls and sanitized failures were added. Accessibility is now derived from explicit `wheelchair=yes`, not words such as “inaccessible” or “ramp”. This tag is provider metadata, not a verified accessibility inspection.
5. The public OSRM demo route was treated as walking merely because `/foot/` appeared in the URL. A configured foot-routing server is now required, and missing distance/duration/invalid geometry no longer becomes fabricated measurements. Public Nominatim defaults were removed to avoid implicitly sending personal GPS queries to a provider with incompatible privacy/use constraints.
6. Independent UI subscriptions caused duplicate5s polling. `SecureApi.watchGet` now shares one polling stream per identity revision/resource for pairing, snapshots and breadcrumb reads, cancels when the last listener leaves, and caches no response across account changes. Each fetch still rechecks backend authorization. Mounted hidden pages and distinct resources can still poll; full-path payload cost remains.
7. Removed unused public DB diagnostic; restricted browser origins; added sanitized parser/error responses; limited cleartext to Android debug builds. Fixed missing iOS Google Maps initialization/photo permission description; gated unsupported map platforms; skipped Mapbox calls without a valid public-token configuration. Profile/ETA network images now require HTTPS.

Secret review: a metadata-only scan of first-party tracked/unignored source and backend source/config found no recognized private-key, service-account-key or high-confidence vendor-secret literals in source. This is **not** proof that every possible secret format is absent. The server `.env` contains configured DB credentials and an unused JWT secret; no values were printed/copied. Keep it server-only and outside commits/backups shared with others. Firebase client keys are public project identifiers, not authorization; their API restrictions still need console review. No privileged service-account credential was found in the inspected first-party source. Existing historical Git objects, ignored binary artifacts, cloud console restrictions, OS credential stores and access permissions were not exhaustively scanned.
